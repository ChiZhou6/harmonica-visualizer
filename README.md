# 三角洲行动 · 口琴可视化曲谱叠加层 v9.1

悬浮在屏幕最顶层的半透明曲谱窗口，左侧是控制面板，右侧用圆角音符块展示三角洲口琴曲谱。

## 零基础用法（推荐）

成品在 `D:\AI\DF Harmonica\三角洲口琴曲谱_发布版\`：

- **`三角洲口琴曲谱.exe`** —— 双击即用，不需要装 Python，不需要任何命令行操作
- `使用说明.txt` —— 白话图文说明（对齐、按键、配色、加曲子、常见问题）
- `config.json` —— 用记事本打开可改透明度、面板宽度、按键绑定、曲谱文件夹等
- `songs\` —— 曲谱文件夹（默认位置），每首一个 txt，可在面板里点选或按 Shift+F7 切换

exe 会自动在**它自己所在的文件夹**里读取/生成 `config.json` 与 `songs\`，整个文件夹可以随便挪到别的电脑上用。
窗口位置与大小会记进 `config.json`，对齐一次以后每次启动都在原位。
曲谱文件夹也可以改成别处（见 [曲谱文件夹](#曲谱文件夹v8-新增)）。

### 重新打包 exe

改了代码后双击 `重新打包exe.bat`（或执行）：

```
python -m PyInstaller --noconfirm --distpath dist --workpath build HarmonicaScore.spec
```

用的是 `HarmonicaScore.spec`（**瘦身配置**）：程序只用到 QtCore / QtGui / QtWidgets，
spec 里把用不到的 Qt 二进制过滤掉，**45.8 MB → 22.2 MB**。

被过滤掉的大件（都不需要）：`opengl32sw.dll`(7.7M 软件 OpenGL)、QML/Quick(5M)、
Qt6Pdf(2.5M)、Qt6Network + OpenSSL(3.4M)、Qt6OpenGL、以及一堆用不到的插件。

> ⚠️ 改 spec 的 `DROP` 名单后**必须**跑 `_tests/_t_zip_clean.py` 验证：
> 它会把 zip 解压到临时目录、**把 PATH 剥到只剩系统目录**（排除本机 venv 里 PySide6 帮忙）后启动 exe
> —— "本机能跑但别人电脑跑不了"就是这么漏出去的。
> ⚠️ 不要开 UPX（`upx=False`）：压缩过的 exe 杀软误报率明显更高。

产物：`dist\HarmonicaScore.exe`（约 22 MB，单文件）。杀毒软件可能对 PyInstaller 打包程序误报，
添加信任即可；未签名 exe 首次运行 Windows 会弹"已保护你的电脑"→ 更多信息 → 仍要运行。

#### 打包成发布用的 zip

```bash
python _pack_release.py        # 在 D:\AI\DF Harmonica\ 下
```

把 `三角洲口琴曲谱_发布版\` 打成 `三角洲口琴曲谱_v8.zip`（约 21 MB）。
发布版**故意不放 `config.json`** —— 里面的 `geometry` 是本机对齐好的窗口位置，
对别人没意义（首次运行会自动生成默认配置）。zip 里的中文文件名带 UTF-8 标志，避免乱码。

### 左侧控制面板

- **热键按钮**：8 个按钮（跟随演奏 / 隐藏窗口 / 下一首 / 调整窗口 / 从头重来 / 面板穿透 / 添加曲谱 / 退出程序），右侧标注对应快捷键，**点一下 = 按一次快捷键**
  - ⚠️ 【面板穿透】是单向陷阱：穿透后面板自身也点不动了，按钮文字变成「已穿透」、右侧照常显示热键（Shift+F10）提示逃生方式（Shift+F10 切回，或 Ctrl+Alt+Q 退出）
  - ⚠️ 【隐藏窗口】按钮同样是"把自己也收起来"的单向操作 → 点下去先显示 0.8 秒提示条（写明恢复按键）再真正隐藏，`PanelWindow._delayed_hide` 里还要判 `isVisible()`，否则用户这 0.8 秒内按热键隐藏后，定时器会把窗口又反过来显示出来
  - 面板按钮 8 行（`PANEL_ROWS`）：跟随演奏 / 隐藏窗口 / 下一首 / 调整窗口 / 从头重来 / 面板穿透 / 添加曲谱 / 退出程序
  - ⚠️ v9 起按钮**按热键号从小到大排**（Shift+F5 → F11）→ 最常用的「隐藏窗口」不再排第一
    （原设计是「最常用所以放最上」，这次按用户要求让位给排序规则）
- **曲谱列表**：点选直接切歌，当前曲目高亮并带彩色侧条；滚轮翻页
  - v8：放不下时右侧**自动出现滚动条**（轨道 + 滑块），支持滚轮 / 拖滑块 / 点轨道翻页，文字宽度会给滚动条让位，两者不叠字
- **音调六色指示**：本音 / 降调 / 半音 / 升调 / 半音+降调 / 半音+升调，当前按下的那个高亮（面板 2 行 × 3 列）
- **状态行**：曲名、剩余音符数
- **输入检测指示灯**：任何被监听的键被按下时显示「检测到：F8」「检测到：，」等，用于快速确认程序能否读到你的键鼠

**面板布局是自适应且不会互相挤占的**（v8 重写 `_compute_layout`）：头部信息区固定，底部按钮区**从面板底边往上排**，列表吃中间剩下的空间；面板变矮时按钮先自动变矮（25→19px），列表最少保留 1 行；列表绘制被 `setClipRect` 裁在列表区内，因此**任何面板高度下都不会出现按钮被切掉 / 列表压住按钮**。窗口最小缩放尺寸相应从 420×320 提到 420×360，旧 config 里过矮的 `geometry` 会被判为无效并回退默认大小。

**灯带**（窗口最底部那条细横条）：把它对齐到游戏口琴按键的**上沿**即可。
灯带颜色实时反映你当前按住的修饰键：

| 灯带颜色 | 音调 | 游戏内操作 |
|----------|------|-----------|
| 白 | 本音 | 不按任何修饰键 |
| 绿 | 降调 | 长按鼠标左键 |
| 紫 | 半音 | 长按鼠标中键 |
| 蓝 | 升调 | 长按鼠标右键 |
| 黄 | 半音+降调 | 同时按住鼠标中键 + 左键 |
| 红 | 半音+升调 | 同时按住鼠标中键 + 右键 |

界面里**不绘制琴键数字与键帽**——对齐和演奏时直接看游戏原版 UI。

## 鼠标穿透模型（v5 起，重要）

窗口由**两个 HWND** 组成，因为实测确认一条硬约束：

> `WM_NCHITTEST` 返回 `HTTRANSPARENT` 的"按区域穿透"只在**同一进程/线程**内把鼠标消息让给下层窗口，
> **跨进程无效** —— 而游戏是另一个进程。所以"一个窗口按区域穿透"的方案会让音符区挡住游戏点击，必须放弃。
> 可靠的做法只有 `WS_EX_TRANSPARENT`（整窗穿透），它是跨进程生效的。

| 窗口 | 覆盖区域 | 鼠标行为 |
|------|----------|----------|
| 音符层（全宽） | 整块背景板 + 8 通道 + 灯带 + 提示气泡 | 锁定后**始终整窗穿透**（`WS_EX_LAYERED \| WS_EX_TRANSPARENT \| WS_EX_NOACTIVATE`） |
| 左侧面板（独立小窗） | 曲目信息 / 音调 / 列表 / 热键按钮 | 正常命中测试，**吃掉**落在其上的点击，不抢焦点；调整模式下可拖动缩放整窗 |
| 调整模式（Shift+F8） | 两层 | 音符层临时去掉穿透以便拖动缩放；面板按钮仍可点 |

- 面板窗口由叠加层驱动同步几何（`moveEvent` / `resizeEvent` → `sync_panel()`），永远贴在左侧、同高，视觉上是一个整体。
- **v9 新增第三个窗口 `SubPanel`**：紧贴主面板下方（宽度跟随主面板；主面板贴到屏幕底边时自动改挂到上方），
  内容是跟随模式倍速（数值 + 进度条 + −/＋ 按钮）。单独开一块的原因：倍速只在跟随模式生效，
  塞进主面板会把 8 行热键按钮挤扁（按钮高度已经压到下限 16px）。它的显隐跟随主面板
  （`toggle_visible` 一起收/放）、穿透跟随 `panel_interactive`。
- `panel_interactive=false` 或按 **Shift+F10** → 面板也加 `WS_EX_TRANSPARENT`，整个界面彻底不接鼠标。
- 点面板**不会**让这次点击漏到游戏（面板窗口是实心命中区），所以点按钮不会误开枪。
- 面板内容按约 12fps 节流刷新（音调指示、检测提示、剩余音数）。
- **背景只允许一层（v9.1 起的硬规则）**：那块半透明大板由**叠加层独家绘制**，左侧面板**不再自己画底**
  —— 以前面板又叠了一层黑，左面板就比音符区暗一档，看着像"两块板没拼好"；小面板则自画与叠加层
  **完全相同**的底色（同色同 alpha、同样只一层，alpha 取自 config 的 `bg_alpha`），三块区域才对得上。
  ⚠️ 用 `QPainterPath` 做"圆角矩形 ∪ 直角矩形"裁剪时**必须显式 `setFillRule(Qt.WindingFill)`**：
  Qt 默认奇偶填充会把两个子路径的重叠区当成挖空 —— 这正是"小面板右边像被切掉 12px"的元凶
  （同款写法在 v9 之前也用在主面板上，接缝处那道竖条就是它）。
  **对接**：小面板贴在主面板下/上方时，用 `square_plate_corner()` 把主面板那一侧的圆角补成直角、
  小面板朝向主面板的一侧也补直角，两块板连成一条直边（否则中间会露出 12×12 的桌面缺口）。
  回归测试：`_t_sub.py` 第 12 组。

## 音符块（v6 改版）

圆角药丸块，块内**只显示该按的按键字母**（z x c v b n m ,），块越长 = 需要按得越久。
颜色与灯带一致：暖白=本音、绿=降调、紫=半音、蓝=升调、黄=半音+降调、红=半音+升调。
（v5 的圆形徽章 ♪/b/#/^ 已按用户要求去掉——音调信息由颜色承载。）

## 工作方式（v8.2 起两种模式，Shift+F5 或面板按钮切换；v9 加倍速）

### 经典模式（默认：堆叠消除）

音符块不自动下落，全部从下往上堆叠；最靠近灯带的那个块带白描边（当前目标），
按下它对应的按键即可消除它，随后整叠音符平滑下落一层（160ms 缓动），继续下一个。
不需要精确节奏与时长，玩家自己掌握节拍，**导入曲谱也最简单**——只要按顺序记录音符。
按错键时该通道灯带上方闪一道红作为提示（300ms 淡出）。
**消除碰撞特效**：按对的一瞬间，灯带上泛起一圈同色光晕并扩散淡出（约 0.32s，
径向渐变 + 扩散细环），音符消失时能明确看到"消在这里"。
弹完显示「演奏完成」，1.2 秒后自动从头开始（`loop=false` 可关闭）。

### 跟随演奏模式（v8.2 新增 / v8.3 按住消除 / v9 全音按住 + 倍速，音游式）

为带完整节奏标注的曲谱设计（如 Dr-hydra 曲谱库的谱面）。音符块按
`BPM + 每音拍数` 换算成真实时间从上方下落，落到底部判定线（灯带）的瞬间即该音的起音时刻。

状态机：`idle 待命 → countdown 倒计时 → playing 演奏 → done`

- **idle**：切到跟随模式后不自动开始。第一个音静止在判定线上方 `follow_lead` 秒处并高亮，
  提示「弹对第一个音开始」；玩家按对第一个音的键即触发倒计时（这次点击不消除任何块）。
- **countdown**：窗口中央大数字倒计时 `countdown_seconds`（默认 3）秒；期间按键不判定。
- **playing：每个音都要"按住才消"（v9，口琴本来就要长按）**：按对（键位一致且时刻差 ≤ `follow_window`）
  的那一瞬间只算**接住**（通道闪光，但块不消失），进入
  `follow_hold = {"idx","ch","state","start","dur","released"}`；块继续自然下落，
  **判定线以下的部分被真正裁掉不画** → 看到的就是判定线在一点点把它吞进去
  （配亮描边 + 判定线上一条随进度收缩的同色光带）。按满这个音的时值才真正消除并放碰撞光晕。
  - 吃掉时间 = `max(该音拍数 × spb, hold_min_seconds × 倍速)`：**一个音几拍就要按住几拍**
    （超短音有 0.15s 地板，免得手指还没感觉到"按住"音就没了）。因几何同步，按满时整块
    刚好滑到判定线下方 → "吃完"和"消失"是同一时刻。
  - 中途松手超过 `hold_grace`（默认 0.2s）→ 中断，剩余部分进 `follow_fade` 继续变暗落走 + 通道红闪。
  - 按住期间该音不判 miss、其他按键被忽略（否则连点会把开始时刻一直往后刷、这个音永远吃不完）。
  - **按住不放会自动接住下一个音**（`_follow_auto_catch`）：同通道连音（如 `1 1 1 1`）只要
    手指还按着、下一个音又进了判定窗就直接接上 —— 和真实口琴一样，按住那个音，谱面走到哪就吹到哪。
    不同通道的音不会误接。
  - `keyboard_monitor=false` 读不到按住状态时一律视为按住（避免永远完不成）。
- 超过窗口仍未按 → 标记 miss（音符变暗落走、指针前进，节奏不中断）；miss 的音也进
  `follow_fade`，继续变暗落走而非凭空消失。
- **倍速（v9）**：`Shift+↑` / `Shift+↓`（或下方小面板的 ＋/－ 按钮）按 10% 步进调整，范围 20% ~ 200%。
  倍速只乘在"播放时间"这一处（`_follow_play_time`），下游就自动全对：
  - 下落速度 ×rate，**块与块的屏幕间距不变**（只是整体走得更快，不会跑出屏幕）；
  - 按住时长 ÷rate（200% 时 4 拍的音只需真实按住 1 秒）→ 与节奏保持同步；
  - 判定窗口 ×rate → **真实时间上的窗口恒定**，越加速不会越难命中；
  - 演奏中改倍速会重新对齐起点，画面不会突然跳一下。当前倍速显示在叠加层右上角与下方小面板上。
- **经典模式完全不受影响**，仍是按一下即消（音没有长短之分，长短由玩家自己把握）。
- 时间对齐：idle/countdown 把第一个音钉在判定线上方 lead 秒处（有前奏的曲子前奏被压缩），
  倒计时结束进入 playing 时从该位置平滑续接；小节边界精确，小节内休止按连续近似。

可调参数（config.json）：`mode` / `follow_speed`（下落速度 px/s，默认 200）/
`follow_lead`（默认 2.0s）/ `follow_window`（判定窗口，默认 0.20s）/
`hold_min_seconds`（最短按住时长，真实秒，默认 0.15；调 0 = 完全按时值）/
`hold_grace`（松手宽限，默认 0.2s）/ `follow_rate`（倍速，默认 1.0，夹在 0.2 ~ 2.0）/
`countdown_seconds`（默认 3）。

> v6 移除了自动下落模式；v8.2 借助 Dr-hydra 谱面的节奏信息把它重新做了回来。

## 曲谱格式（两种，自动识别）

1. **自带简谱格式**：`TITLE=` / `BPM=` 头 + 数字简谱（详见 `使用说明.txt`）。
2. **Dr-hydra 曲谱库格式（v8.2 新增）**：GitHub 项目
   [Dr-hydra/Delta-Force-Harmonica](https://github.com/Dr-hydra/Delta-Force-Harmonica)
   导出的"人可演奏版文本谱"——每小节含「简谱 / 键位 / 节奏」三行，键位为
   `Z X C V B N M ,` + 修饰标记 `+`(升调) `-`(降调) `#`(半音)。
   解析入口 `parse_dfh_tab()`，由 `is_dfh_tab()` 自动识别（含「键位标记」行即命中）。
   节奏列按 `durationLabel` 的逆映射还原成拍数（`4`=1拍、`8`=0.5拍、`·`=附点 ×1.5、
   `Xb`=直接读数字拍）。文本谱不含休止位置，小节内按音符连续近似、小节边界精确。

## 8 个通道的按键映射

| 通道 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|------|---|---|---|---|---|---|---|---|
| 按键 | z | x | c | v | b | n | m | **,** |
| 简谱 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8（高音1） |

在 `config.json` 的 `note_keys` 中可改（逗号写 `comma`，句号写 `period`）。

> ⚠️ v5 及更早版本第 8 键绑的是 VK `0xBE`（句号 `.`），导致按逗号 `,`（VK `0xBC`）无反应。v6 已修正为逗号。

| Shift+F5 | 切换 经典模式 / 跟随演奏模式（v8.2） |
| **Shift+↑** | **跟随倍速 +10%（最快 200%）** |
| **Shift+↓** | **跟随倍速 −10%（最慢 20%）** |
| Shift+F10 | 面板可点击 / 面板也鼠标穿透 |
| Shift+F11 | 打开 / 关闭【添加 / 编辑曲谱】窗口 |
| Shift+F12 | 开始 / 结束 录音 |
| Ctrl+Alt+Q | 退出 |

⚠️ **F 区热键一律加 `Shift` 前缀（Shift+F3 / Shift+F5 ~ Shift+F12）**：游戏里也常用 F4~F12，
不加修饰键会抢键 / 误触发。裸按 F4~F12 时本程序毫无反应 —— 这正是防冲突的设计。

⚠️ 热键读取的是**物理按键状态**，若键盘 F 区被 Fn 锁定为媒体键，请改用面板按钮（按钮不依赖键盘）。

#### 界面上的热键文字不许写死

面板按钮右侧、屏幕提示、编辑器按钮上的热键文字一律走 `hotkey_text(cfg, action, joiner)` /
`Overlay.hk(action)`，**从 config 现取** → 改 `config.json` 后界面提示自动跟着变，
不会再出现"按钮写着 F6、实际要按 Shift+F6"这种对不上的情况（v8 修）。

- `format_combo("shift+f6") -> "Shift+F6"`；`format_hotkey("shift+f6|shift+f2") -> "Shift+F6/Shift+F2"`
- 按钮里位置不够时"逐个丢掉后面的备选键"，还是不够就整个不显示（见 `PanelWindow._draw`）

#### 一个动作绑多个键

`config.hotkeys` 的值支持两种写法：

- `+` = **同时按下**（组合键），如 `"quit": "ctrl+alt+q"`
- `|` = **备选键**，任一组合按下都触发，如 `"toggle_visible": "shift+f6|shift+f2"`

```json
"toggle_visible": "shift+f6|shift+f2|ctrl+h"   // 三组都能隐藏
```

内部结构：`Overlay.hotkey_vks[action]` 是 **list[tuple[vk,...]]**（备选组合的列表），
`_poll_input` 用 `any(all(st.get(v,False) for v in c) for c in combos)` 判定。
旧的单值写法（`"f6"`）依然兼容。

默认只绑一个键（Shift+F6）。担心被游戏抢占的话，可以在 config.json 里自己加备用键
（如 `"toggle_visible": "shift+f6|shift+f2"`）——解析与提示文字都会自动跟上。

⚠️ **不要做"老配置自动升级"的隐式迁移**：`load_config()` 每次启动都跑，
按"旧默认值"回写会变成每次启动覆盖用户设置（`main()` 里那句
`ov._save_config({"hotkeys": cfg["hotkeys"]})` 只补缺失项、不改已有值）。

## 自己做曲谱（v7 新增）

入口：面板上的【✚ 添加曲谱】按钮，或 **Shift+F11**。

| 操作 | 入口 |
|------|------|
| 录音（弹一遍就记下来） | **Shift+F12** / 【● 开始录音】 |
| 撤销一个音 | Ctrl+Z / 【撤销一个音】 |
| 清空 | 【清空】（有内容时确认） |
| 载入面板上选中的曲谱来改 | 【载入当前曲谱】 |
| 读入外部 .txt | 【从文件导入…】 |
| 保存到曲谱文件夹 | Ctrl+S / 【保存到曲谱库】（重名会问是否覆盖） |
| **静默保存（不弹框、不要求窗口在前台）** | **Shift+F3**（重名自动改名「某某2」） |
| 导出到任意位置 | Ctrl+E / 【导出为文件…】 |
| **换曲谱文件夹** | 【曲谱文件夹…】（选回默认目录 = 恢复「跟着程序走」） |
| 用资源管理器打开曲谱文件夹 | 【打开文件夹】 |

- 录音复用**同一条** `GetAsyncKeyState` 轮询链路，不新增任何钩子/模拟输入 —— 安全性质不变。
- 录音时叠加层显示红色脉冲点 +「录音中 + 已录 N 个音」，**不自动弹出编辑器**（避免挡住游戏画面）。
- 录入的文本**追加**在文本框末尾（每 16 个记号换行），不会写进 `//` 注释行或 `TITLE=`/`BPM=` 行。
- 保存成功后自动 `reload_songs()` 刷新面板列表，无需重启。

⚠️ **为什么保存有两个键**：Qt `QShortcut` 默认是 `Qt.WindowShortcut`，只有编辑器在前台时 `Ctrl+S` 才触发。
玩家在游戏里按 Shift+F12 结束录音时编辑器并不在前台 → `Ctrl+S` 会「没反应」。因此**额外**提供 Shift+F3：
它走全局轮询热键，不依赖焦点、不弹任何框、重名自动改名，结果写在 HUD 提示条上。

## 曲谱文件夹（v8 新增）

默认 = 程序旁边的 `songs\`（`config.songs_dir` 为空，跟着 exe 走，方便整个文件夹搬运/分享）。
改成别处只需要改一个字段：

```json
{ "songs_dir": "" }                       // 默认：exe 旁边的 songs
{ "songs_dir": "D:\\我的口琴曲谱" }        // 绝对路径
{ "songs_dir": "songs2" }                 // 相对路径（相对 exe 所在目录）
```

代码里把它做成"运行期可变"而不是常量，避免到处改引用：

- `DEFAULT_SONGS_DIR` —— 永远指向 `BASE_DIR/songs`
- `resolve_songs_dir(cfg)` —— 算出最终目录（空 / 相对 / 绝对三态）
- `apply_songs_dir(cfg)` —— 更新模块级 `SONGS_DIR`（目录不存在就建）+ 失败时回退默认
- `is_default_songs_dir(path)` —— 判断是不是默认目录（用来决定 `songs_dir` 存空还是存路径）

启动顺序也相应调整为 `load_config() → apply_songs_dir(cfg) → ensure_data_files() → load_songs()`，
这样首次运行生成示例曲谱时用的就是**用户配置的目录**，而不是硬编码的默认目录。

编辑器里的【曲谱文件夹…】用 `QFileDialog.getExistingDirectory` 选目录，选中的若是默认目录就把
`songs_dir` 写回 `""`（保证"跟着程序走"）；新目录里没有 `.txt` 时会问一句要不要把自带示例曲谱复制过去。
`--selftest` 会打印当前实际使用的曲谱文件夹。

## 安全说明（无封号风险设计）

| 项目 | 情况 |
|------|------|
| 键鼠钩子 | ❌ 不安装（不调用 SetWindowsHookEx），不依赖 keyboard/mouse 钩子库 |
| 模拟输入 | ❌ 不发送任何输入（不调用 SendInput / mouse_event / keybd_event） |
| 读游戏内存 | ❌ 完全不读取，也不知道游戏进程是否存在 |
| 进程注入 | ❌ 不注入、不挂载 DLL、不 Hook DirectX |
| 联网 | ❌ 无任何网络请求 |
| 唯一系统调用 | ✅ `user32.GetAsyncKeyState` 读取按键/鼠标键状态（灯带配色、热键、面板按钮）+ 画一个普通置顶分层窗口 |

也就是说：它只是一个"显示在屏幕上的画板"，加上"看一眼你按了哪些键和哪个鼠标键"。
键鼠轮询与绘制都在唯一的 UI 线程里完成，程序内没有后台线程。

要彻底静默：把 `config.json` 的 `keyboard_monitor` 设为 `false`，则完全不读键鼠（灯带恒为白色、热键失效，仅纯视觉显示）。

## 曲谱格式（songs 文件夹里的 .txt）

```
TITLE=小星星
1 1 5 5 6 6 5 - | 4 4 3 3 2 2 1 -
b3 #5 ^1 8 - 0
```

- 空格分隔，每个音 1 拍；音后面跟 `-` 或独立的 `-` 表示延长 1 拍（越长按得越久）
- 前缀 `b` = 降调、`#` = 半音、`^` = 升调，无前缀 = 本音
- 组合前缀 `#b`（半音+降调，黄）与 `#^`（半音+升调，红）；解析顺序无关（`#b`/`b#` 等价、`#^`/`^#` 等价）
- `8` 或 `i` = 第 8 通道（`,` 键）；`0` = 休止符
- `|` 小节线、`//` 注释行，仅作可读性
- `BPM=` 字段保留但已无作用（v6 起不再自动下落）

### 注入鼠标的两个坑（踩过，排查很久）

1. `SendInput` 做绝对移动必须是 `MOUSEEVENTF_ABSOLUTE(0x8000) | MOUSEEVENTF_MOVE(0x0001)`。
   **只发 `0x8000` 时返回 1 但光标不动**（静默失败），脚本会误以为"已经挪开了"。
2. 注入鼠标键前，光标必须离开**本进程的所有窗口**（要把所有可见窗口矩形都过一遍）：
   右键落在自己窗口的标题栏会弹出**本进程的模态系统菜单** → 卡住消息循环 → 那段时间的按键全漏，
   症状很像产品 bug（"只有一部分键被录进去"）；落在桌面/任务栏则会抢走前台焦点。

> 结论：**"真机 e2e 挂了但离屏测试全过"时，先怀疑注入脚本（标志位/光标位置/焦点），别急着改产品逻辑。**
